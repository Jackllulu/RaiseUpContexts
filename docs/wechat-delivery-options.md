## 用户实际怎么用（方案 A）

**感觉**  
微信里只有小程序「新生日历」，没有要关注的品牌公众号。日历上同时列出给父亲、给母亲的事项（每条标明角色）。提醒在「服务通知」，点回小程序。一个人用一个微信即可看全；伴侣若要自己手机收通知，再用自己的微信登录同一家庭（不是为了「解锁」对方内容）。

**到达**  
一次性订阅：用户点同意，通常**一票发一条**该模板。打开小程序（看完、勾选、保存）时再申请续票（一次弹窗多个模板，有上限）。票记在**这个微信**上，不按角色拆库存。当天父亲+母亲事项合并为 **≤1 条**。

**配置**  
全在小程序：上海/其他、预产期或生日、父亲/母亲两套状态、预设标签 + 1 自定义、该微信静音、可选邀请另一微信加入家庭。

**无公司的硬约束**

- 个人/个体小程序：**不能**做企业认证服务号，也就**没有**服务号模板消息当备用到达。  
- 个人可申请的订阅号与本产品明确**不做**（用户不要品牌号）。  
- 长期订阅多在政务/医疗/教育等类目，且常要更完整的主体资质；v1 **不赌**长期订阅，也不为了它去挂医疗类目。  
- 部分类目、支付、插件对个人主体更严，只影响扩展，不改变「小程序 + 一次性订阅」这条主路径。

**与节奏**  
T-14 / T-7 / 科普每 3 天 / T0 停，都靠手里还有票。两周不打开 → 科普会断，**这是已接受的行为**。小程序内提示「通知次数不足，点续订」；静音时不弹；不发客服补救。

## 平台能力对照（为何不选别的）

| 能力 | 与已锁定主体 | v1 |
| --- | --- | --- |
| **小程序一次性订阅** | 个人/个体可用 | **采用** |
| 小程序长期订阅 | 类目与资质不确定 | 不用；不挡 A 上线 |
| **认证服务号模板** | **必须企业认证** | **不可用** |
| 订阅号群发 | 个人或可申请，但是群发、非按家庭日历 | **明确不做品牌号** |
| 客服消息 | 仅短时互动窗口 | **禁止当节拍通道** |
| 公众号图文 | 依赖公众号 | **不做** |

## 曾列方案（均已否决，仅存档）

- **B 小程序 + 认证服务号模板**：到达更稳，但要公司与年审 → **无公司，关闭**。  
- **C 长期订阅**：批文不确定，且不作为 v1 条件。  
- **D 仅公众号**：个性化日历做不到，且用户不要订阅号/服务号。

不推荐（维持）：客服刷到达、订阅号群发当日历、为订阅去申请医疗问诊类目。

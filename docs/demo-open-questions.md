# 新生日历：演示里待确认的开放问题

用户不在时先把可点演示做出来。下列三项**仍待用户确认**，产品锁（方案 A、共享查看、深度 A、静音不打破）不重开。

演示 UI 顶部有「待确认」条，与本文同步。

---

## 1. 个人主体类目 / 一次性订阅模板能否过审

通道已锁定为**个人/个体小程序 + 一次性订阅消息**。尚未确认：

- 实际可过审的**服务类目**（不赌医疗问诊类目）
- 后台能申请到的**一次性订阅模板名称/字段**（只能写摘要）

演示用本地「余票」数字代替微信授权弹窗，不调用任何微信 API。

---

## 2. 细稿权威来源与法务免责原文

孕晚–1 岁样例写得「细」，但**不是定稿**：

- 权威来源清单未指定
- 法务免责全文未审定（「我的 · 免责声明」为占位口径：非问诊、无剂量处方、上海/其他差异、标签非病历）

骨架阶段（孕早中、1–7 岁）按 MVP 只给标题+一两句。

---

## 3. 实现时采用的调度假设（请确认或改）

| 假设 | 演示中的做法 |
| --- | --- |
| 孕周日历 | 预产期 = 孕 **40 周 0 天**；某孕周 T0 = 预产期 − (40−n)×7 天 |
| 出生覆盖 | 一旦填写生日，0–7 岁用生日算整月/整岁；已过 T0 的孕期项进补课包，不连推 |
| 未出生的月龄项 | 仍用预产期当「预期生日」生成未来辅食/入园骨架，便于一条时间轴看完 |
| 「其他」品类 T0 | 行政窗口默认 **T-14 / T-7 / T0**（当成「必要时加 T0」） |
| 科普网格 | 自 T-14 每 3 天；若网格未落到 T0 则**补 T0** 后停 |
| 夜间 | 演示时钟 21:00–7:59 视为夜间；顺延到次日（21 点后 +1 天）。若顺延日已过该条 T0 → **不推、进补课包** |
| 日合并 | 同一模拟微信、同一演示日，多条父亲/母亲节拍合成 **1 条**服务通知、耗 **1 票** |
| 断票 | 余票为 0 时日历可看、横幅续订、不发通知 |
| 静音 | 按当前模拟微信；静音中不弹续票、不耗票、不发通知 |
| 第二微信 | 同浏览器切换「微信 B」+ 邀请码，家庭最多 2 个登录 |
| 标签 | 预设可多选；自定义全家庭 **1 个**（再保存即替换）；`有效至 ≥ 今天` 才生效 |
| 改地区 | 只影响目录过滤（上海条 vs 其他兜底）；不重发已模拟发出的通知 |

若上述与预期不符，改调度即可，不必改 IA。
